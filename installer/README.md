# K11C Installer 0.5.0

## 실행

ZIP을 쓰기 가능한 로컬 폴더에 모두 풀고 `k11c-installer.exe`를 실행합니다.
실행 파일 2개와 `resources` 폴더를 함께 보관하세요.
Windows x64 및 WebView2 Runtime이 필요합니다.

오른쪽 위에서 English, 한국어, 繁體中文, Español, 日本語와 시스템·라이트·다크 테마를
선택합니다. 언어와 테마는 다음 실행에도 유지됩니다.

Rockusb가 설치되어 있으면 그대로 사용합니다. 없으면 관리자 권한 요청 후
내장 드라이버를 설치합니다. 취소했다면 프로그램을 다시 열어 재시도할 수 있습니다.

## 설치·복구

**작업 선택 → 연결 → 백업 선택 → 파일 선택 → 확인·실행**

1. **HAOS 설치** 또는 **백업 복원**을 선택합니다.
2. 보드를 정상 종료하고 전원과 SD 카드를 분리한 뒤 MASKROM으로 PC에 연결합니다.
   RKDevTool 등 다른 USB 작업 프로그램은 닫으세요.
3. **장치 준비 후 다음**을 누릅니다. 이미 준비된 RAM Loader는 재사용합니다.
   USB 표시가 Maskrom으로 남아 있어도 실제 응답으로 준비 상태를 판단합니다.
   읽기 제한 안내가 나오면 전원을 완전히 분리한 뒤 MASKROM으로 다시 연결하세요.
4. **전체 백업** 또는 **백업 없이 진행**을 선택합니다.
   백업을 선택하면 현재 eMMC를 압축 저장하고 USB 재읽기·파일 대조 후 진행합니다.
   필요한 백업을 이미 보관했다면 백업 없이 다음 단계로 이동할 수 있습니다.
5. 설치라면 공식 HAOS를 다운로드하거나 PC의 `.img.xz` / `.img`를 선택합니다.
   복구라면 FULL `.k11cbackup` 또는 전체 디스크를 덤프한 `.img`를 선택합니다.
6. **설치 준비** 또는 **복원 준비**를 누르고 대상 장치·용량·기록 범위·복구용 백업을 확인합니다.
   `ok`를 입력한 뒤 **기록 시작**을 누릅니다.
7. 기록·재읽기 검증이 완료되면 USB와 전원을 분리하고 SD 카드 없이 다시 켭니다.

설치·전체 복원은 현재 OS와 데이터를 덮어씁니다. 백업을 선택한 경우 앞 단계의 검증된
전체 백업을 재사용합니다. 설치 미리보기·실행 준비에서 원본 eMMC 전체를 다시 대조하지 않습니다.
실행 준비 중에는 **취소**할 수 있습니다. 실제 기록이 시작되면 취소할 수 없습니다.
기록·읽기 대조 중 전원과 USB를 유지하세요. 실패하면 화면의 오류와 `data/plans` 작업 기록,
백업 파일을 보관하고 연결을 확인하세요.

완료 후 진행 정보와 입력값은 초기화됩니다. 완료 안내는 **확인**을 누르거나
다른 메뉴로 이동하면 사라집니다. 백업 파일·다운로드 캐시·작업 기록은 유지됩니다.

## HAOS 설치 파일

**공식 다운로드** 화면에 들어가면 Home Assistant 공식 저장소의 버전을 자동으로 불러옵니다.
버전별 generic-aarch64 이미지와 SHA-256을 가져와 검사합니다. 저장된 파일은 해시가
일치할 때 재사용합니다. **내 PC에서 선택**으로 공식 이미지를 직접 가져올 수도 있습니다.

선택한 HAOS와 정확히 호환되는 Connectivity와 U-Boot를 함께 준비합니다.
HAOS는 공식 저장소에서, Connectivity는 GHCR에서 다운로드합니다. K11C 저장소의
호환 목록으로 버전·커널·이미지 해시를 확인하고 U-Boot를 함께 준비합니다.
Windows에서 초기 데이터 영역을 생성하므로 Docker·WSL·에뮬레이터 설치는 필요 없습니다.
포터블 ZIP에는 HAOS·Connectivity 이미지가 없으며, 검증된 조합만 설치할 수 있습니다.
공식 OS 파티션은 유지하고 초기 데이터 파티션에 Connectivity를 사전 설치합니다.
첫 부팅부터 자동 시작하며 저장소도 등록됩니다. 이후 HAOS는 공식 A/B 업데이트를,
Connectivity는 앱 저장소 업데이트를 사용합니다.

## 백업과 복원

새 백업은 실행 파일 옆의 `backup` 폴더에 단일 파일로 저장합니다.

**고급 기능 → 고급 백업·복원 → 복원**에서는 현재 장치를 추가로 백업하지 않습니다.
선택한 파일을 검사한 뒤 대상과 기록 범위를 확인하고 `ok`를 입력해 복원합니다.
현재 상태도 보관하려면 복원 전에 **백업**에서 따로 저장하세요.
설치·복구 마법사에서는 전체 백업 여부를 선택할 수 있습니다.

복원 화면에 들어가면 목록을 자동으로 불러옵니다. **백업 파일 가져오기**로 등록한
전체 RAW `.img`도 새로고침·재실행 후 목록에 남습니다. RAW 파일은 복사하지 않으므로
원래 위치에 보관하세요. 원본이 이동되거나 없어지면 다시 가져와야 합니다.

- `FULL-YYMMDD-HHMMSS.k11cbackup`: eMMC 사용자 영역 전체.
- `BOOT-YYMMDD-HHMMSS.k11cbackup`: K11C 부팅 펌웨어 예약 영역과 주·보조 GPT.
- `HAOS-YYMMDD-HHMMSS.k11cbackup`: HAOS의 8개 파티션. OS·앱·설정·사용자 데이터 포함.

날짜는 PC의 현지 시각입니다. 이름이 겹치면 번호를 덧붙입니다.
빈 영역도 생략하지 않고 무손실 압축하므로 복원 시 원래 바이트를 그대로 기록합니다.
실제 파일 크기는 데이터에 따라 달라지며, 암호화되거나 이미 압축된 데이터는 크게 줄지
않을 수 있습니다. eMMC 전체를 읽는 시간은 압축으로 줄어들지 않습니다.
미완료 파일은 `.partial`로 남고 복원 목록에 표시되지 않습니다.

새 백업은 빠른 Zstandard 압축을 사용하며, USB 읽기와 PC의 압축 작업을 겹쳐 처리합니다.
읽기·압축 → eMMC 재대조 → 백업 파일 검사 순서로 진행합니다.
기존 XZ 방식의 `.k11cbackup`도 복원할 수 있습니다. 새 백업은 이 업데이트 이후의 프로그램으로 열어주세요.

FULL은 **eMMC 사용자 영역** 전체입니다. 별도 하드웨어 영역인 boot0·boot1·RPMB·OTP는
포함하지 않습니다. 연결한 보드와 같은 eMMC 용량에 복원합니다.
Android의 암호화 키나 별도 보안 상태가 바뀐 경우 기존 사용자 데이터 복구까지 보장하지 않습니다.

복원은 백업 속 OS·펌웨어·데이터를 그대로 기록합니다. 새 U-Boot나 Connectivity를
추가하지 않습니다. 제조사의 RKFW/RKAF 펌웨어 패키지와 Android sparse 이미지는
전체 디스크 덤프가 아니므로 직접 복원 입력으로 사용할 수 없습니다.
기존 `.img` 덤프는 선택한 원본 경로에서 읽습니다. 파일을 이동했다면 다시 선택하세요.
`backup` 폴더에 있는 `.k11cbackup`은 메타데이터를 확인해 그대로 사용하며 중복 복사하지 않습니다.
미리보기에서는 범위·용량·형식을 확인하고, 실제 복원 직전에 전체 파일을 한 번 검사합니다.

## 고급 기능

맨 위의 **고급 백업·복원**에서 먼저 **백업** 또는 **복원**을 선택합니다.
**저장장치 확인 필요**가 표시되면 **장치 준비**를 누릅니다. 설치 화면으로 이동할 필요는 없습니다.
확인이 끝나면 해당 디스크에서 사용할 수 있는 백업 범위가 표시됩니다.
백업 화면에서는 저장 범위를 선택합니다. 복원은 다음 두 종류 중 하나를 선택합니다.

- **제조사 이미지**: K11C용 Android·Linux 전체 시스템 `.img`를 선택합니다.
  RKFW 패키지는 내장 Rockchip 도구, 전체 디스크 이미지는 기록·대조 엔진을 사용합니다.
  `rootfs.img`·`boot.img` 같은 단일 파티션 파일은 지원하지 않습니다.
- **저장된 백업**: 이 프로그램으로 저장한 백업이나 전체 디스크 덤프를 되돌립니다.

복원 목록에는 파일을 선택하기 전부터 FULL·BOOT·HAOS 태그와 복원 범위가 표시됩니다.
종류는 파일명이 아닌 내부 정보로 판별하며, 형식을 확인할 수 없는 파일은 선택할 수 없습니다.
선택한 파일의 상세 범위는 최종 확인창에도 표시됩니다. **작업 다시 선택**으로 돌아갈 수 있습니다.
정상 K11C HAOS 파티션 구성이면 FULL·BOOT·HAOS를 선택할 수 있습니다.
Android 등 다른 OS 또는 알 수 없는 구성에서는 FULL만 지원합니다.
GPT가 손상되어도 전체 백업은 가능합니다.

부분 복원은 현재 HAOS 파티션 구성이 백업과 같아야 합니다.
OS나 파티션 구성이 달라졌다면 FULL 복원을 사용하세요.
이전 버전의 부팅 영역 백업은 기존 `data/backups` 폴더에서 계속 읽습니다.
이 백업에는 사용자 데이터가 없습니다.

- **U-Boot 업데이트**: 검증된 배포 펌웨어만 교체하며 OS와 사용자 데이터는 유지합니다.
- **Connectivity 관리**: 실행 중인 HA에 연결해 앱을 제거하거나 기본 설정으로 재설치합니다.
  기존 앱의 HA 백업을 확인한 뒤 진행합니다. 유선 LAN에서 사용하세요.
- **저장장치 정보**: 용량과 GPT 정보를 조회합니다.
- **GPT 검사·복구**: 두 파티션 테이블을 대조하고 정상 사본으로 복구합니다.
  서로 다른 정상 파티션 구성을 임의로 선택하지 않습니다.

U-Boot·GPT 작업에는 복구용 백업이 필요합니다. 고급 복원은 추가 백업 없이 진행합니다.
제조사 이미지 설치 시 다른 Rockchip USB 장치는 분리하세요.
마지막 확인 없이는 eMMC에 기록하지 않습니다.

## 개발

Node.js, Go 1.26.3 이상, Rust MSVC 및 Visual C++ Build Tools가 필요합니다.
`npm ci`, `npm run build`, `npm test`, `npm run test:ui:mutation`, `npm run test:mutation`, `npm run package`.
이미지 검사: `node scripts/mutation-images.mjs`, `node scripts/verify-images.mjs`.
후자는 패키지의 실행 파일로 최신 공식 이미지를 실제 다운로드하므로 인터넷과 저장 공간이 필요합니다.
기록 경로 조건 반전 검사: `node scripts/mutation-flash.mjs`, `node scripts/mutation-archive.mjs`.
구성요소·앱 관리 조건 검사: `node scripts/mutation-components.mjs`.
Windows 준비 엔진 조건 검사: `node scripts/mutation-native.mjs`.
빌드 결과: `release/K11C-Installer-0.5.0`.

- `K11C_RELEASE_INPUTS`: 선택 사항인 빌드 입력 폴더. `loader`, `firmware`, `rockusb`, `rockchip`, `native`를 읽습니다. 기본값은 소스에 포함된 `resources`입니다.
- `K11C_BUILD_TOOLS`: 선택 사항인 로컬 Rust 도구 경로. 생략하면 PATH의 cargo를 사용합니다.
- `K11C_GO`: 선택 사항인 Go 실행 파일 경로. 기본값은 PATH의 go입니다. Go 1.26.3 이상이 필요합니다.
- `K11C_DRIVER_SOURCE`: 원본 Rockusb INF/CAT/SYS 폴더
- `K11C_LOADER_SOURCE`: 검증된 K11C RAM Loader 파일
- `K11C_FIRMWARE_SOURCE`: 검증된 K11C r24 U-Boot 파일
- `K11C_FIRMWARE_MANIFEST`: 위 파일의 빌드 정보. 생략하면 U-Boot 파일명 뒤에 `.manifest.txt`를 붙입니다.

GitHub의 **Code → Download ZIP**에 USB 로더, 서명된 드라이버, 제조사 도구와 현재
U-Boot가 포함됩니다. ZIP을 푼 뒤 `installer` 폴더에서 위 명령을 실행하면 됩니다.
기존 포터블 ZIP이나 SDK, HAOS·Connectivity 데이터 없이 빌드할 수 있습니다.
개별 SOURCE 변수는 해당 입력만 덮어씁니다. 입력 검사만 하려면
`node scripts/build.mjs --check-inputs`를 실행하세요.

Loader와 드라이버의 지정 SHA256이 다르면 허용하지 않습니다.
API와 검증 범위는 api-contract.md 및 VERIFICATION.md에 정리되어 있습니다.

## 배포 구성요소

소스의 `seed/README.md`에 로컬 호환성 검증과 목록 생성 방법이 있습니다.
GitHub의 `installer-catalog.json`은 검증된 HAOS·Connectivity·커널·U-Boot 조합과
해시를 지정합니다. 별도 사전설치 이미지 배포나 원격 CI 준비 작업은 필요 없습니다.
HAOS가 새로 나왔다고 구버전 Connectivity를 강제로 설치하지 않습니다.
