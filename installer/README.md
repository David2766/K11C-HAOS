# K11C Installer 0.4.0

## 실행

ZIP을 쓰기 가능한 로컬 폴더에 모두 풀고 `k11c-installer.exe`를 실행합니다.
실행 파일 2개와 resources 폴더를 함께 보관하세요.
Windows x64 및 WebView2 Runtime이 필요합니다.

Rockusb가 설치되어 있으면 그대로 사용합니다. 없으면 관리자 권한 요청 후
내장 드라이버를 설치합니다. 취소했다면 프로그램을 다시 열어 재시도할 수 있습니다.

## 보드 연결과 백업

1. HA에서 정상 종료한 뒤 전원을 분리하고 SD 카드를 빼세요.
2. RKDevTool 등 다른 USB 작업 프로그램을 닫으세요.
3. 기존과 같은 방법으로 K11C를 MASKROM 모드로 PC에 연결하세요.
4. 하단의 **장치 준비 후 다음**을 누르고 연결한 보드가 K11C인지 확인하세요.
5. Loader 연결 확인이 끝나면 백업 단계로 이동합니다. **백업 후 다음**을 누르세요.
6. 백업 저장·대조가 끝나면 이미지 선택 단계로 이동합니다. 백업 파일은 **02 백업 → 백업 폴더 열기**에서 확인할 수 있습니다.

장치가 이미 Loader 상태면 **장치 확인 후 다음 → 백업 후 다음**으로 진행합니다.
현재 장치의 백업을 완료했다면 **다음: 이미지 선택**으로 중복 백업 없이 이동합니다.
작업 중에는 USB 케이블과 전원을 유지하세요. 다른 보드에 이 Loader를 사용하지 마세요.

## 화면 이동

**연결 → 백업 → 이미지 선택 → 설치** 순서로 한 단계씩 표시합니다.
각 단계의 하단 진행 버튼 하나로 작업하고, 성공하면 다음 단계로 이동합니다.
실패하거나 취소하면 현재 단계에서 다시 시도할 수 있습니다.
하단 **이전**이나 상단 단계 이름으로 이동할 수 있으며, 작업 중에는 이동 버튼이 잠깁니다.

## HAOS 이미지 준비

보드를 연결하지 않아도 **03 이미지 선택**에서 준비할 수 있습니다.

- **공식 다운로드 → 버전 선택 → 다운로드 후 다음**. 화면에 들어가면 목록을 자동으로 불러옵니다.
  GitHub의 home-assistant/operating-system 릴리스에서 generic-aarch64 이미지와
  해당 파일의 SHA-256을 읽어옵니다. 특정 HAOS 버전이나 해시는 프로그램에 고정하지 않습니다.
  이미 받은 파일은 공식 해시와 일치하면 다시 다운로드하지 않습니다.
  같은 실행 중에는 목록을 재사용하며, 필요할 때 새로고침할 수 있습니다.
  조회에 실패하면 **다시 시도**를 누르거나 **내 PC에서 선택**을 이용하세요.
- **내 PC에서 선택 → 파일 선택 후 다음**: `.img.xz` 또는 `.img`를 선택합니다.
  원본은 그대로 두고 실행 폴더의 `data/images/prepared`에 준비합니다.

두 경로 모두 주·보조 GPT, HAOS 파티션 구성, ARM64 EFI 부팅 파일과 저장된 파일을 검사합니다.
검사가 완료되면 설치 확인 단계로 이동하며, 자동으로 eMMC에 기록하지는 않습니다.
이미지 단계로 돌아오면 준비한 파일을 재사용합니다. 소스나 버전을 바꾸면 새로 준비해야 합니다.
로컬 파일은 구조 검사이며 공식 SHA-256 대조 여부를 구분해 표시합니다.
압축 파일과 펼친 이미지 저장 공간이 필요합니다. 작업 중 **취소**할 수 있으며,
네트워크 응답을 기다리는 동안에는 취소 완료에 잠시 시간이 걸릴 수 있습니다.

## HAOS 설치

1. **04 설치 → 설치 준비**를 누르세요.
2. 이미지와 대상 eMMC를 검사한 뒤 현재 부팅 영역을 자동 백업합니다.
3. 확인창에서 대상 장치·용량·백업 위치를 확인하고 `K11C`를 입력하세요.
4. **기록 시작**을 누르고 **HAOS 설치 완료**가 나올 때까지 기다리세요.
5. USB와 전원을 분리하고, SD 카드 없이 전원을 다시 연결하세요.

**새 설치는 기존 OS·Home Assistant 설정·사용자 데이터를 삭제합니다.**
HA 전체 백업은 별도로 보관해야 합니다. 프로그램의 부팅 영역 백업은 전체 디스크 백업이 아닙니다.

공식 generic-aarch64 이미지의 파티션 내용과 식별자는 유지하며, 앞부분에 K11C 부팅
펌웨어 공간을 확보합니다. 동봉된 r24 U-Boot와 실제 eMMC 용량에 맞춘 GPT를 기록합니다.
HAOS 시스템 파일을 수정하거나 다시 빌드하지 않습니다. 이후 OS 업데이트는 HAOS에서 받습니다.
최초 부팅에서는 HAOS가 데이터 파티션을 확장합니다.

## 고급 기능

- **U-Boot 업데이트**: 동봉된 K11C r24로 부팅 펌웨어만 교체합니다. OS·사용자 데이터는 유지됩니다.
- **백업 복원**: `data/backups`에 있는 검증된 백업을 선택합니다. 백업 당시와 같은 USB 포트에서
  같은 장치를 연결하세요. 파티션 구성이 바뀌었거나 GPT가 손상된 백업은 복원하지 않습니다.
  이전 포터블 버전의 백업은 폴더 전체를 새 버전의 `data/backups`에 복사하면 표시됩니다.
- **GPT 검사**: 실제 eMMC의 주·보조 GPT를 읽어 CRC·식별자·파티션 구성을 검사합니다.
- **GPT 복구**: 정상 사본을 기준으로 잘못된 GPT를 재작성합니다. 두 정상 사본의 파티션 구성이
  다르면 자동으로 선택하지 않습니다. 이미 정상이면 기록하지 않습니다.

모든 기록 작업은 실행 전 자동 백업·최종 확인을 거치며, 기록한 범위를 다시 읽어 대조합니다.
기록 중에는 전원이나 USB를 빼지 마세요. 프로그램 종료도 검증이 끝날 때까지 차단됩니다.
실패하면 `data/plans`의 작업 기록과 `data/backups`를 보존하세요. 자동 재시도나 재부팅은 없습니다.
설치 도중 중단됐다면 다시 설치해야 하며, 부팅 영역 복원만으로 지워진 HA 데이터를 되돌릴 수 없습니다.

## 백업 파일

`data/backups/k11c-…/`에 다음 파일을 저장합니다.

| 파일 | 내용 |
| --- | --- |
| gpt-primary.bin | LBA 0–33: 보호 MBR, 주 GPT |
| reserved-gap.bin | LBA 34–63: 예약 영역 |
| uboot-reserved.bin | LBA 64–34815: K11C U-Boot 예약 영역 |
| gpt-backup.bin | 실제 eMMC 끝 33개 섹터 |
| manifest.json | 장치 정보, 정확한 범위·길이·SHA256, GPT 검사 결과 |
| SHA256SUMS | 파일별 SHA256 |

USB에서 두 번 읽은 결과와 저장 파일의 해시를 대조합니다. 실패하거나 중단된
폴더는 `.partial`로 남습니다. `.partial` 폴더는 복원용 백업으로 사용하지 마세요.
GPT에 문제가 있어도 복구에 필요한 원본 바이트는 백업되며, 화면에 검사 결과를 표시합니다.
표준 128×128 GPT 외의 레이아웃은 정상으로 판정하지 않습니다.

이 백업에는 HA 설정·사용자 데이터 및 eMMC boot0/boot1이 포함되지 않습니다.
HA 데이터는 Home Assistant에서 별도로 백업하세요.

## 개발

Node, Rust MSVC 및 Visual C++ Build Tools가 필요합니다.
`npm ci`, `npm run build`, `npm test`, `npm run test:ui:mutation`, `npm run test:mutation`, `npm run package`.
이미지 검사: `node scripts/mutation-images.mjs`, `node scripts/verify-images.mjs`.
후자는 패키지의 실행 파일로 최신 공식 이미지를 실제 다운로드하므로 인터넷과 저장 공간이 필요합니다.
기록 경로 조건 반전 검사: `node scripts/mutation-flash.mjs`.
빌드 결과: `release/K11C-Installer-0.4.0`.

- `K11C_RELEASE_INPUTS`: 배포 ZIP을 풀어 얻은 `resources` 폴더. `loader`, `firmware`, `rockusb`를 함께 읽습니다. 생략하면 소스 옆의 `resources`를 사용합니다.
- `K11C_BUILD_TOOLS`: 선택 사항인 로컬 Rust 도구 경로. 생략하면 PATH의 cargo를 사용합니다.
- `K11C_DRIVER_SOURCE`: 원본 Rockusb INF/CAT/SYS 폴더
- `K11C_LOADER_SOURCE`: 검증된 K11C RAM Loader 파일
- `K11C_FIRMWARE_SOURCE`: 검증된 K11C r24 U-Boot 파일
- `K11C_FIRMWARE_MANIFEST`: 위 파일의 빌드 정보. 생략하면 U-Boot 파일명 뒤에 `.manifest.txt`를 붙입니다.

소스 저장소에는 펌웨어·드라이버·빌드 결과를 넣지 않습니다. 현재 배포 ZIP의 `resources`를
지정하면 별도의 SDK나 개발자의 원래 폴더 없이 빌드할 수 있습니다. 개별 SOURCE 변수는
해당 입력만 덮어씁니다. 입력 검사만 하려면 `node scripts/build.mjs --check-inputs`를 실행하세요.

Loader와 드라이버의 지정 SHA256이 다르면 허용하지 않습니다.
API와 검증 범위는 api-contract.md 및 VERIFICATION.md에 정리되어 있습니다.
